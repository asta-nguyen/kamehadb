# Plan 06-01: Interactive Engine Matrix Section

**Phase:** 6 — Landing Polish
**Wave:** 1 (independent — no deps on 06-02/06-03)
**Requirements:** LMAT-01, LMAT-02, LMAT-03

## Goal

Add an interactive engine matrix section to the landing page with status badges (SQL/document/cache/vector/ledger), a supported-features checklist per engine, and a one-click "Try in Docker" snippet with copy-to-clipboard.

## Files

| Action | File                                       |
| ------ | ------------------------------------------ |
| Create | `landing/src/lib/engines.ts`               |
| Create | `landing/src/components/engine-matrix.tsx` |
| Edit   | `landing/src/components/home-view.tsx`     |

## Steps

1. **Create `landing/src/lib/engines.ts`** — vendored canonical engine data:
   - `ENGINE_TYPE` union: `'sql' | 'document' | 'cache' | 'vector' | 'ledger'`
   - `EngineInfo` interface: `{ kind, label, type, port, dockerImage, dockerSnippet, features: { label, supported }[] }`
   - `ENGINES: EngineInfo[]` — 12 entries mirroring `ALL_KINDS` from `packages/shared/src/schemas.ts`. Kind values match `KIND.*` exactly.
   - `ENGINE_TYPE_LABELS: Record<ENGINE_TYPE, string>` — display labels.
   - `ENGINE_TYPE_FILTERS: ENGINE_TYPE[]` — filter options.
   - Comment documenting manual-sync with `packages/shared/src/schemas.ts`.
   - Docker snippets use the docker-compose defaults from AGENTS.md (ports, users, passwords). File-based engines (SQLite, DuckDB) show a file-path snippet.
2. **Create `landing/src/components/engine-matrix.tsx`** — client component:
   - Type filter row (All / SQL / Document / Cache / Vector / Ledger) using `useState` for active filter.
   - Responsive grid of engine cards filtered by active type.
   - Each card: engine label, type badge (color-coded), features checklist (check/cross icons), Docker snippet with copy button.
   - Copy button uses `navigator.clipboard.writeText` with a "Copied!" state feedback.
   - Card click expands/collapses the Docker snippet section.
   - Uses `motion` for entrance animations (matching existing home-view pattern).
   - Uses `cn` from `@/lib/utils` for classnames.
3. **Edit `landing/src/components/home-view.tsx`** — insert `<EngineMatrix />` section:
   - Import `EngineMatrix` from `./engine-matrix`.
   - Place between "Why KamehaDB" section and "AI Query Generation" section.
   - Add a `SectionHeading` with title "Every engine, one workspace" and subtitle.
4. **Verify:** `npm --prefix landing run build` passes (includes type checking).

## Verify Gate

- `npm --prefix landing run build` green
- Engine matrix renders 12 cards with type badges
- Filter row filters cards by type
- Docker snippet copy button works
- Kind values in `engines.ts` match `KIND.*` from `packages/shared/src/schemas.ts`
