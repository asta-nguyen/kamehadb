The `SchemaChangelogEntry` type does not carry the `source` field — it only has `snapshotId`, `capturedAt`, and `changes`. To show the source badge, we need to cross-reference the snapshots list. The `useSchemaSnapshots` hook returns `SchemaSnapshotSummary[]` which also doesn't have `source`. However, the `snapshot_data` JSON in the metadata store does contain `source` (added in Plan 03-01 Task 1).

The simplest approach that avoids a new sidecar route: add `source` to the `SchemaSnapshotSummary` type and populate it in the sidecar's `toSnapshotSummary` function. This is a minimal shared contract change.

Add optional `source` to `SchemaSnapshotSummary`:

```ts
export type SchemaSnapshotSummary = {
  readonly id: string;
  readonly connectionId: string;
  readonly capturedAt: string;
  readonly tableCount: number;
  readonly source?: SchemaSnapshotSource;
};
```

**Step 2: apps/sidecar/src/routes/sql-schema.ts**

Update `toSnapshotSummary` to include `source`:

```ts
function toSnapshotSummary(snapshot: SchemaSnapshotRecord): SchemaSnapshotSummary {
  return {
    id: snapshot.id,
    connectionId: snapshot.connectionId,
    capturedAt: snapshot.capturedAt,
    tableCount: snapshot.tables.length,
```

**File: apps/desktop/src/components/schema-timeline.tsx**

The `useSchemaWatcherStatus` hook polls every 10s (set in Plan 03-01). When `lastCaptureAt` changes, it means a new auto-snapshot was captured. We use a `useEffect` to detect this change and invalidate the changelog + snapshots queries, then show a toast.

1. Add `useEffect` and `useRef` to the React import at the top of the file (if not already imported):

```ts
import { useEffect, useRef } from 'react';
```

2. Inside the `SchemaTimeline` component, after the watcher status hook, add a ref to track the previous `lastCaptureAt` and an effect to detect changes:

```ts
// Detect auto-capture events by tracking lastCaptureAt changes from the watcher status poll.
// When a new capture is detected, invalidate the changelog and snapshots queries so the
// timeline refreshes, and show a toast notification.
const prevLastCaptureRef = useRef<string | null>(watcherStatus?.lastCaptureAt ?? null);
useEffect(() => {
  const currentCapture = watcherStatus?.lastCaptureAt ?? null;
  if (currentCapture && currentCapture !== prevLastCaptureRef.current) {
    prevLastCaptureRef.current = currentCapture;
    // Invalidate both the changelog and snapshots so the timeline and diff view refresh.
    void queryClient.invalidateQueries({ queryKey: QUERY_KEYS.SCHEMA_CHANGELOG(connectionId) });
    void queryClient.invalidateQueries({ queryKey: QUERY_KEYS.SCHEMA_SNAPSHOTS(connectionId) });
    toast.success(`Auto-snapshot captured — ${new Date(currentCapture).toLocaleTimeString()}`);
  } else if (!currentCapture) {
    prevLastCaptureRef.current = null;
  }
}, [watcherStatus?.lastCaptureAt, connectionId, queryClient]);
```

This effect runs whenever `watcherStatus?.lastCaptureAt` changes (i.e., every 10s poll that detects a new capture). It invalidates the TanStack Query caches for the changelog and snapshots, causing the timeline to re-fetch and show the new entry. The toast gives immediate user feedback.

The schema diff view already uses `useSchemaSnapshots(connectionId)` to populate its snapshot selector dropdowns. Since auto-snapshots are saved to the same `schema_snapshots` metadata table via the same `saveSchemaSnapshot()` function, they automatically appear in the snapshot list. The only change needed is to ensure the diff view's snapshot list refreshes when auto-captures happen.

The diff view is a separate tab from the timeline. When the user opens the diff view, `useSchemaSnapshots` fetches the current list. If an auto-capture happens while the diff view is open, the list won't refresh unless invalidated.

Add a watcher status poll + invalidation effect to the diff view, mirroring the timeline's approach:

1. Add imports:

```ts
import { useEffect, useRef } from 'react';
```

```ts
const { data: watcherStatus } = useSchemaWatcherStatus(connectionId);
const prevLastCaptureRef = useRef<string | null>(watcherStatus?.lastCaptureAt ?? null);
```
