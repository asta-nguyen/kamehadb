# Receiving code review

When receiving feedback from a reviewer or user:

1. **Read** the complete feedback without reacting.
2. **Understand** — restate the requirement in your own words or ask.
3. **Verify** — check against codebase reality before implementing.
4. **Evaluate** — decide whether the suggestion fits this codebase.
5. **Respond** — give a technical acknowledgment or reasoned pushback.
6. **Implement** — address one item at a time and verify each.

Avoid performative agreement ("You're absolutely right!", "Great point!").
State the fix or push back with technical reasoning. If feedback is unclear,
ask about all unclear points before implementing any.

Push back when a suggestion breaks existing functionality, the reviewer lacks
full context, it violates YAGNI, or it conflicts with architectural decisions.
