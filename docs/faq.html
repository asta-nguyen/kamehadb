FAQ

What is KamehaDB?

KamehaDB is a local-first, cross-platform database GUI with built-in AI. It connects to PostgreSQL, MySQL, SQLite, MongoDB, and Redis, letting you browse schemas, run queries, and generate SQL through conversation.

How does AI-SQL generation work?

KamehaDB's AI chat sends your database schema context (table definitions, columns, foreign keys) to an LLM provider. The AI uses this context to generate accurate SQL queries. You can ask questions like "show me all users who signed up last month" and the AI will write the query.

What AI providers are supported?

KamehaDB supports any OpenAI-compatible API provider: OpenAI (GPT-4o, GPT-4o-mini), Ollama (local or cloud), and 9Router. Local Ollama is recommended for privacy and cost savings.

Is my data sent to the cloud?

Your database credentials are stored locally in an encrypted SQLite database. If you use a cloud AI provider (OpenAI, 9Router), query context is sent to that provider. Using local Ollama keeps all data on your machine.

What's the difference between KamehaDB and DBeaver/Navicat?

KamehaDB differentiates by: (1) Built-in AI for SQL generation, (2) Local-first architecture with encrypted credentials, (3) Modern React + Tauri stack, (4) ER diagram visualization with ReactFlow.

Why Tauri instead of Electron?

Tauri uses Rust for the backend instead of Node.js, making binaries smaller (~10MB vs ~150MB), startup faster, and memory usage lower. The web frontend is still React.

Can I connect to remote databases?

Yes. KamehaDB connects to any PostgreSQL, MySQL, or Redis instance accessible from your machine. Simply provide the host, port, username, and password (or connection string).

How do I report bugs or request features?

Open an issue on GitHub with details about the problem or desired feature.
