## Task 9 — Exact additional SQL paging

Verified: 2026-10-14, same unchanged HEAD/dirty-source preservation. This records implementation and available native checks, not all-platform/all-server certification or the final benchmark.

### Implemented contract

- Cached PostgreSQL/SQLite/MySQL/MariaDB/SQL Server/Oracle adapters and owned DuckDB children assign private random engine/adapter scopes. Version-2 bookmarks bind that scope and schema as well as the existing view shape. Scope cannot be supplied through JSON/Wails; identical tables on another/reopened adapter reject the bookmark. Existing PostgreSQL/SQLite eligibility stays conservative.
- Additional eligible single non-null keys use native parameterized comparisons and the existing metadata TTL, budget, navigation and fallback contracts. Unsigned 64-bit and signed/unsigned 128-bit anchors remain exact; native floating-point keys do not qualify as integral originals.
- Oracle only qualifies declared `NUMBER(1..38,0)` or supported text identity. Numeric keys use decimal-text projection and validated digit-string `TO_NUMBER` binding, with physical-column numeric ordering; unknown/fractional NUMBER stays offset. SQL Server binds native VARCHAR/Unicode text appropriately and casts integer parameters, not indexed columns; uniqueidentifier remains fallback.
- DuckDB's pinned native driver rejects scalar high-bit uint64 parameters and UHUGEINT decoding/inferred parameters. Native regressions reproduced both failures. Exact text projection plus VARCHAR-first parameter casts fix unsigned/wider continuation without converting the indexed comparison/order column. Native HUGEINT cells use safe decimal strings beyond JavaScript's exact range.
- Private metadata-preview RPC, protocol 2, avoids redundant child metadata reads; matching helper/version installation checks were repeated. Assets remain unpublished and older release compatibility is not claimed.
- ClickHouse never infers uniqueness from its sorting key. Duplicate-key native fixture remains offset, and supplying a foreign cursor now errors instead of silently ignoring it (failure reproduced before fix). HTTP native-block streaming replaces server wait-for-full-result buffering after actual driver/server tests verified complete-row byte stops and rejection of late-error partial GUI results. This is not a hard native-block/process-memory ceiling.
