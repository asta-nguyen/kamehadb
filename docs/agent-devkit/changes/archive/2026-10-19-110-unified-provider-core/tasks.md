# Unified database provider core tasks

Issue: [#110](https://github.com/asta-nguyen/kamehadb/issues/110)

## Design

[Unified database provider core](design.md)

## Global Constraints

- Reuse and relocate existing adapter implementations and their tests; do not rewrite database operations.
- Preserve all existing query/result limits, SQL optional capabilities, cancellation behavior, TLS settings, no-replay rules, read-only constructors and DuckDB isolation.
- The entire `dbcore/` tree must have no imports of `github.com/asta-nguyen/kamehadb/internal/...` or Wails.
- Keep credential storage, profile persistence, GUI request ownership, metadata/result caching, history, Wails, terminal jobs, schema workflows, AI orchestration and MCP authorization in the application.
- Do not create a nested module, separate repository, npm package, release workflow, or new dependency.
- MCP reuses relocated provider constructors and bounded-read capabilities, not GUI sessions.
- No core accessor or GUI lookup returns a concrete driver adapter.
- Do not start core implementation or adapter relocation until the open footprint plan's Tasks 10, 11 and 12 are implemented and verified under that plan.
- Do not add a generic process runner, JDBC/JRE support, shared worker runtime, downloadable-provider marketplace, a large driver manifest, or a new JSON-RPC protocol in this change.
